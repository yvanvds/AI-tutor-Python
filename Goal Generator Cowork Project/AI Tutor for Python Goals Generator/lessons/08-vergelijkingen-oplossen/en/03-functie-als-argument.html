Until now the bisection loop worked for one function, which had to be called f. For another equation you would copy the whole loop. You don't have to: you can pass a function as an argument, just like a number or a list.

A function as a parameter

def value_table(f, start, step, count):
    values = []
    for i in range(count):
        values.append(f(start + i * step))
    return values

def square(x):
    return x * x

def cube(x):
    return x ** 3

print(value_table(square, 0, 1, 5))
print(value_table(cube, 0, 1, 5))

Output:

[0, 1, 4, 9, 16]
[0, 1, 8, 27, 64]

The first parameter of value_table is a function. Inside it is called f and you call it like any function, with f(...). Which function that is, the call decides: the first time square, the second time cube. What the function is called outside doesn't matter inside, just as with any other parameter.

The name, not the call

print(value_table(square(2), 0, 1, 5))

Output:

TypeError: 'int' object is not callable

square without parentheses is the function itself. square(2) is a call: Python works that out first and passes on the result, the number 4. Inside value_table, f(...) then tries to call a number, and that can't be done. So pass the name, without parentheses.

One bisection for every equation

def bisection(f, a, b, tolerance):
    while b - a > tolerance:
        m = (a + b) / 2
        if f(a) * f(m) < 0:
            b = m
        else:
            a = m
    return (a + b) / 2

def g(x):
    return x ** 3 - x - 1

print(round(bisection(g, 1, 2, 0.000001), 4))

Output:

1.3247

What changes from problem to problem becomes a parameter: the function, the two limits and the tolerance. The loop itself stays the same. The function gives back the solution and the main script prints it.

Another problem, the same solver

A small company sells a product for 6 euros per item. The costs are 400 euros fixed, 2 euros per item, plus 0.005 times the square of the quantity because large quantities get more expensive. From how many items on is there a profit?

def profit(quantity):
    revenue = 6 * quantity
    costs = 400 + 2 * quantity + 0.005 * quantity ** 2
    return revenue - costs

print(profit(0), profit(200))
print(round(bisection(profit, 0, 200, 0.001), 1))

Output:

-400.0 200.0
117.2

You only write the function that belongs to the problem: profit is revenue minus costs, and the break-even point is where it becomes zero. At 0 items the profit is negative, at 200 positive, so there is a sign change in between. The function you pass has exactly one parameter; the fixed numbers of the problem are inside it.

Why this way?

One solver function that you test well once is more reliable than a copy of the loop per equation. If there is an error in it, you fix it in one place. And a new equation only costs you a small function and one call.

With a function as an argument your search method becomes a tool that you can put to work on any problem.
