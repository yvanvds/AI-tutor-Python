With for you know in advance how many times something is repeated. Often you don't know that: you keep asking until the input is right, or you keep calculating until a limit is reached. That is what while is for: repeat as long as a condition is true.

The while loop

counter = 1
while counter <= 3:
    print(counter)
    counter = counter + 1
print("done")

Output:

1
2
3
done

Python checks the condition each time at the top, just before a new iteration. If it is true, the block runs once more; if it is false, the program carries on after the loop. In between, Python doesn't look: if the condition becomes false in the middle of the block, that block is still finished first.

Just follow the example: with counter = 4, counter <= 3 is false, so the loop stops and done appears.

The loop that never stops

A while loop only stops if something happens in the block that at some point makes the condition false. If you forget that, the loop runs on forever:

counter = 1
while counter <= 3:
    print(counter)

Here counter never changes, so counter <= 3 stays true forever and the screen fills up with ones. Check for every while loop you write: which line in the block brings the end closer?

While, not until

Tasks often say "repeat until the user types stop". The condition of while, however, says when you keep going, not when you stop. So you have to turn the sentence around: repeat until the answer is "stop" becomes repeat as long as the answer is not "stop" — while answer != "stop":.

Checking input

A classic use of while: keep asking for input until it is valid.

number = int(input("Enter a number from 1 to 10: "))
while number < 1 or number > 10:
    number = int(input("Invalid, try again: "))
print("Chosen:", number)

If the user types something valid straight away, the condition is false straight away and the block doesn't run a single time. If they type 12, the question keeps coming until a valid number appears.

for or while?

The choice follows from the task. If the number of repetitions is fixed — five sides, ten numbers, a hundred stars — then for with range is the natural form. If the end depends on something you only find out while the program runs — a user's input, a value that reaches a limit — then you need while. Everything that can be done with for can also be done with while, but not the other way around.

With that, you can write repetitions where not you, but the program itself decides when they end.
