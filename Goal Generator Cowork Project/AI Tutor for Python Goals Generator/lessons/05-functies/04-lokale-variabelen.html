Een functie werkt in haar eigen afgesloten ruimte. Wat daarbinnen gemaakt wordt, blijft daarbinnen, en dat maakt functies betrouwbaar.

Een eigen werkruimte per aanroep

def met_btw(prijs):
    btw = prijs * 21 / 100
    return prijs + btw

print(met_btw(100))
print(btw)

Uitvoer:

121.0
NameError: name 'btw' is not defined

Bij elke aanroep krijgt de functie een nieuwe, lege werkruimte. De parameter prijs en de variabele btw bestaan alleen daarin, en alleen zolang de aanroep loopt. Zulke variabelen heten lokaal.

Na de return ruimt Python de werkruimte op. In het hoofdscript bestaat er dus geen btw, en ook geen prijs. Het enige wat naar buiten komt, is de teruggegeven waarde.

Dezelfde naam, een andere variabele

def verhoog(getal):
    getal = getal + 1
    return getal

getal = 5
verhoog(getal)
print(getal)

Uitvoer:

5

Er zijn hier twee variabelen die getal heten: één in het hoofdscript en één in de werkruimte van de functie. De functie krijgt de waarde 5 binnen, maakt er in haar eigen ruimte 6 van en geeft die terug. Het hoofdscript doet niets met dat resultaat, en zijn eigen getal is nooit aangeraakt.

Een toekenning binnen een functie verandert nooit een variabele erbuiten, ook niet als beide dezelfde naam hebben.

Teruggeven en opslaan

Een functie die een variabele van buitenaf rechtstreeks wil aanpassen, loopt vast:

teller = 0

def tel_bij():
    teller = teller + 1

tel_bij()

Uitvoer:

UnboundLocalError: cannot access local variable 'teller' where it is not associated with a value

Door de toekenning beschouwt Python teller als een lokale variabele, en die heeft nog geen waarde op het moment dat de rechterkant uitgerekend wordt. De oplossing is altijd dezelfde: de waarde gaat binnen via een parameter, het resultaat komt terug via return, en het hoofdscript slaat het op.

def tel_bij(waarde):
    return waarde + 1

teller = 0
teller = tel_bij(teller)
teller = tel_bij(teller)
print(teller)

Uitvoer:

2

Waarom via parameters

Een functie kan een variabele uit het hoofdscript wel lezen; zo gebruikt een tekenfunctie de turtle t. Voor de gegevens waarmee ze rekent, is dat toch geen goed idee.

Een functie die alles via haar parameters krijgt, begrijp je door alleen die functie te lezen. Je kan ze testen met gelijk welke waarden, en bij dezelfde argumenten geeft ze altijd hetzelfde resultaat. Een functie die afhangt van een variabele ergens anders in het script, geeft plots iets anders zodra iemand die variabele verandert.

Lijsten gedragen zich anders

def voeg_nul_toe(lijst):
    lijst.append(0)

getallen = [1, 2, 3]
voeg_nul_toe(getallen)
print(getallen)

Uitvoer:

[1, 2, 3, 0]

Dit is hetzelfde verschijnsel als b = a bij lijsten: de parameter lijst is een tweede naam voor dezelfde lijst. Een methode zoals append of een toekenning aan een index, zoals lijst[0] = 9, past die ene lijst aan, en dat zie je ook buiten de functie.

Een toekenning aan de naam zelf, zoals lijst = [], maakt alleen een nieuwe lokale variabele en laat de lijst van de aanroeper met rust. Wil je de lijst van de aanroeper niet veranderen, bouw dan in de functie een nieuwe lijst op en geef die terug.

Wie weet wat binnen blijft en wat naar buiten komt, kan van elke functie voorspellen wat ze met de rest van het script doet.
