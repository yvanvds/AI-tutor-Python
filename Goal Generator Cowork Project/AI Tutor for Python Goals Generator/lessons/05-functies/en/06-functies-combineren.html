You rarely solve a bigger problem in one function. You split it into small functions that each have one task, and let them use each other's results.

Functions that call functions

def square(x):
    return x * x

def sum_of_squares(a, b):
    return square(a) + square(b)

print(sum_of_squares(3, 4))
print(square(square(2)))

Output:

25
16

Python always finishes a call completely before it goes on. In sum_of_squares(3, 4), square(3) is worked out first, then square(4), and only then the sum of 9 and 16.

You read nested calls from the inside out: square(2) is 4, and square(4) is 16.

Functions with lists

The list patterns you know, such as adding up, counting, filtering and searching, become reusable when you put them in a function. The list comes in as a parameter and the result goes back with return.

def average(numbers):
    return sum(numbers) / len(numbers)

def above_average(numbers):
    limit = average(numbers)
    result = []
    for number in numbers:
        if number > limit:
            result.append(number)
    return result

scores = [12, 15, 8, 17, 13]
print(average(scores))
print(above_average(scores))

Output:

13.0
[15, 17]

above_average doesn't work out the average itself: it calls the helper function. It also builds a new list and gives that back, so the caller's list stays untouched.

Never copy the code of a helper function into another function. Call it: then every calculation is in one place.

First a plan

Before you write code, you decide which functions you need. For every function, note its name, what goes in and what comes out. For the question of how many prime numbers there are below 50, that plan looks like this:

FunctionInOut
is_prime(n)a whole numberTrue if n is a prime number, otherwise False
count_primes(limit)an upper limitthe number of prime numbers below the limit

The second function doesn't need to know how you recognize a prime number. It asks the first one.

def is_prime(n):
    for divisor in range(2, n):
        if n % divisor == 0:
            return False
    return True

def count_primes(limit):
    count = 0
    for n in range(2, limit):
        if is_prime(n):
            count = count + 1
    return count

print(count_primes(50))

Output:

15

Testing a function

Because a function gives back its result, you test it with a few calls whose answer you know beforehand. Choose ordinary cases and edge cases: the smallest values, zero, an empty or very short list.

print(is_prime(7))
print(is_prime(9))
print(is_prime(2))
print(is_prime(1))

Output:

True
False
True
True

The first three match what you expect. The last one doesn't, because 1 is not a prime number. For n = 1, range(2, 1) is empty: the loop never runs and the function goes straight to return True. One condition at the top solves that.

def is_prime(n):
    if n < 2:
        return False
    for divisor in range(2, n):
        if n % divisor == 0:
            return False
    return True

print(is_prime(1))

Output:

False

The call with the wrong answer points to where the error is. You fix it in one place, and every function that calls is_prime uses the right version from then on.

That is how you build a bigger program out of small pieces that you can each understand and check separately.
